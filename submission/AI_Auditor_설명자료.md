# AI Auditor — 프로젝트 설명자료

> 프로젝트 산출물에서 사람이 확인해야 할 품질 위험과 근거를 먼저 좁혀주는 Local AI 기반 사전 점검 도구

## 1. 프로젝트 소개

AI Auditor는 요구사항정의서·추적표 등 프로젝트 산출물을 분석하고, 누락·중복·불일치와 같은 품질 위험 후보를 제시하는 Windows 데스크톱 애플리케이션입니다. 검사기준에 따라 문서를 점검하고, 발견 내용과 근거·위험도를 확인한 뒤 검사 이력과 보고서로 남길 수 있습니다.

주요 사용 대상은 프로젝트 품질 담당자, PM·PMO, 감리 준비 담당자입니다. 사람이 문서를 검토할 때 반복하는 기본 점검과 결과 문서화 작업을 지원하며, 발견된 Issue의 타당성과 최종 조치는 담당자가 판단합니다.

## 2. 해결하려는 문제

- **문서의 누락과 불일치:** 요구사항 ID 중복·누락, 구현 조건의 불충분한 정의, 산출물 간 추적 연결 누락 등을 여러 문서에서 찾아야 합니다.
- **확인 근거를 정리하는 부담:** 문제를 발견한 뒤에도 관련 문서, 판단 근거와 위험도를 다시 정리해야 합니다.
- **반복되는 검사와 보고서 작성:** 문서 수정 후 같은 기준으로 재점검하고, 결과와 이력을 문서로 남기는 작업이 반복됩니다.

AI Auditor는 문서 등록부터 검사, 근거 확인, 재검사 준비, 이력 조회와 보고서 내보내기까지 하나의 화면 흐름으로 연결합니다.

## 3. 현재 구현된 주요 기능

| 기능 | 내용 |
|---|---|
| 문서 등록·분석 | DOCX · DOC · XLSX · XLS · PDF · PPTX · PPT · HWPX · HWP의 9종 문서 파서 지원 |
| 검사기준 선택 | 감리 사전점검 · 요구사항 정합성 · 변경영향도 · FP 검증 · AI 특화 검증의 5개 영역 |
| 검사 실행 | 전체 카탈로그 105개 중 현재 실행 가능한 규칙 56개. Rule 14개 · AI 11개 · Hybrid 31개 |
| 결과 확인 | Score·Grade·Issue 목록과 각 Issue의 관련 문서, Check Point, Evidence 확인 |
| 위험도 판단 | Impact와 Likelihood를 바탕으로 Severity Matrix를 적용해 위험도 표시 |
| 재검사·이력 | Re-Inspect에서 기존 프로젝트·문서·선택 규칙을 연결하고, 이전 검사결과 조회 |
| 보고서 내보내기 | 검사결과를 DOCX · XLSX · TXT로 저장 |
| Local AI | Qwen3-4B를 llama.cpp로 로컬 실행하여 AI·Hybrid 검사에 활용 |

56개 실행 규칙과 105개 카탈로그 항목은 구분합니다. 105개 전체의 구현을 완료했다는 의미는 아닙니다. 스캔 PDF의 OCR은 현재 지원 범위에 포함하지 않습니다.

## 4. 사용 흐름

1. **프로젝트·문서 등록:** Inspection에서 프로젝트 정보를 입력하고 점검할 산출물을 추가합니다.
2. **검사기준 선택:** 점검 영역과 실행할 규칙을 선택합니다.
3. **검사 실행:** 문서를 분석하고 선택한 규칙을 실행하며 진행 상태를 표시합니다.
4. **결과·근거 확인:** 프로젝트 결과에서 점수·등급·Issue를 확인하고, 개별 Issue의 발견 내용과 근거·위험도를 살펴봅니다.
5. **재검사·이력 확인:** 문서를 수정한 뒤 Re-Inspect로 같은 기준의 검사를 준비하고 이전 검사결과를 조회합니다.
6. **보고서 저장:** Export Report에서 원하는 형식을 선택해 검사결과를 내보냅니다.

검사결과는 확인이 필요한 후보입니다. 담당자가 원문과 근거를 확인해 판단하고 문서를 수정합니다.

## 5. 기술 구성과 AI 활용 방식

| 구성 | 기술·역할 |
|---|---|
| 데스크톱 화면 | Python 3.13 · PySide6 |
| 문서 처리 | python-docx · openpyxl · pypdf · python-pptx 등 문서별 파서 |
| 검사 엔진 | 명시적 조건을 확인하는 Rule, 문맥을 분석하는 AI, 두 방식을 결합하는 Hybrid |
| 로컬 추론 | Qwen3-4B Q4_K_M GGUF · llama.cpp |
| 데이터 저장 | SQLite 기반 프로젝트·검사결과 저장 |
| 검증 | pytest 기반 자동 회귀검증 |

처리 흐름은 **문서 파싱 → 선택 규칙 실행 → 필요 시 Local AI 추론 → Issue·근거·위험도 구성 → 결과 저장·보고서 생성**입니다. 규칙의 실행 방식에 따라 Rule·AI·Hybrid 경로를 사용합니다.

시연 구성은 외부 AI API 대신 PC에서 Qwen3-4B를 실행합니다. 외부 AI API에 문서를 전송하지 않는 로컬 추론 구성이며, 실제 폐쇄망 도입 시에는 해당 환경에서 설치·운영 검증이 필요합니다.

## 6. 실제 시연 사례

| 항목 | 시연 내용·관찰값 |
|---|---|
| 프로젝트 | 요구사항 품질점검 |
| 입력 문서 | 요구사항정의서 DOCX 1개 · 추적표 XLSX 1개 |
| 적용 규칙 | REQ-001 요구사항 ID 누락·중복 점검 / REQ-006 요구사항 완전성 점검 / REQ-018 양방향 추적성 점검 |
| 검사 처리시간 | 434.06초, 약 7분 14초 |
| 결과 | 69점 · D등급 · Issue 후보 7건 |
| 보고서 | Word 보고서 6페이지 생성 |
| 제출 영상 | 실제 프로그램 녹화 편집본, 약 2분 58초 |

영상은 검사 대기 구간을 편집해 문서 등록·검사 시작·완료·Issue 상세·재검사 준비·이력·보고서·Local AI 설정을 보여줍니다. 영상 길이는 실제 검사 처리시간과 다릅니다. Re-Inspect 장면은 재검사 준비 기능을 보여주는 장면입니다.

위 수치는 특정 문서·규칙·PC 환경의 단일 시연 사례입니다. 다른 입력에서 동일 시간·점수·건수를 보장하지 않으며, 후보 7건이 모두 실제 오류라는 의미도 아닙니다.

## 7. 효과측정 — 보고서 작성 자동화

같은 프로젝트의 기존 검사결과를 대상으로, **동일한 요약 8개 항목을 Word 문서로 작성·저장·열어 확인하는 단계**를 비교했습니다.

| 구분 | 수행 내용 | 소요시간 |
|---|---|---|
| 수동 | 빈 Word 문서에 요약표 작성 → 저장 → 다시 열어 항목 확인 | 약 7분 22초 |
| 자동 | Export Report → DOCX 저장 → 열어 같은 항목 확인 | 약 6초 |
| 차이 | 수동 442초 − 자동 6초 | 약 7분 16초 |

공통 요약 항목은 프로젝트명, 부서명(기관명), 프로젝트 구분, 검사일시, 검사유형, Score·Grade, 적용 규칙 수, 전체 이슈 수입니다. 자동 보고서에는 Issue 상세도 생성되지만, 비교의 완료 기준은 요약 8개 항목의 저장·확인입니다.

동일인이 수동→자동 순서로 각 1회 수행했으며, 시간은 제출자가 제공한 근사값입니다. 별도 증빙을 통한 검증은 수행하지 않았고, 수행 순서·익숙함에 따른 영향이 있을 수 있습니다. 사전 준비, 원문 검토, AI 검사·추론과 개별 Issue 판단은 제외했습니다. 전체 검사·감리 업무의 절감률, 평균 성과, 정확도·오류율 변화나 인건비 절감액을 측정한 결과는 아닙니다.

제출용 1장 요약은 `AI_Auditor_Report_Time_Comparison_1page.pdf`, 상세 비교 조건과 원자료는 `REPORT_TIME_METHOD.md`, `report_time_observations.json`, `AI_Auditor_Report_Time_Data.xlsx`에 있습니다.

## 8. 소스코드와 실행

- **GitHub 제출 브랜치:** <https://github.com/jjang99/AI-Auditor/tree/codex/hackathon-submission>
- **소스코드 첨부 파일:** `AI_Auditor_Source_Submission.zip`
- **실행 진입점:** `main.py`
- **주요 소스:** `ui/` 화면, `app/` 문서 처리·검사 서비스·저장소, `rules/` 검사기준·엔진, `tests/` 자동 검증

Windows에서 Python 3.13과 의존성을 준비한 뒤 실행합니다.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Local AI 실행에는 아래 파일을 별도로 준비해야 합니다. 소스 ZIP에는 대용량 모델·실행 바이너리가 포함되지 않습니다.

```text
models/Qwen3-4B-Q4_K_M.gguf
runtime/llama.cpp/llama-server.exe
```

모델 배포처는 <https://huggingface.co/Qwen/Qwen3-4B-GGUF>, 검증한 llama.cpp 런타임은 <https://github.com/ggml-org/llama.cpp/releases/tag/b11312>입니다. DLL 배치와 모델 버전 등 상세 실행 준비는 소스에 포함된 `submission/REPRODUCE_WINDOWS.md`에 정리했습니다. 비공개 GitHub 링크를 사용하는 경우 심사위원의 열람권한이 필요합니다.

## 9. 차별점과 확장 방향

AI Auditor는 문서의 요약을 넘어, **검사기준에 따른 품질 위험 후보를 근거·위험도와 함께 제시하고 재점검·이력·보고서로 연결**합니다. Local AI를 활용해 외부 AI API를 호출하지 않는 문서 점검 흐름을 구성했습니다.

다양한 실제 프로젝트 문서에서 검출 품질과 처리시간을 반복 검증하고, 검출 근거와 규칙 적용 범위를 보완하는 것이 다음 과제입니다. 미구현 카탈로그 규칙의 확대와 반복 측정을 통한 업무 효과 검증은 향후 개선 범위입니다.

**AI가 먼저 짚는 위험, 사람이 완성하는 품질.**
