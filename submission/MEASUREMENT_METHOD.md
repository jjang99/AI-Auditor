# 효과측정 방법과 실제 결과

## 무엇을 측정했는가

검토자가 직접 수동 검토를 수행할 수 없어 생산성 비교는 측정하지 않았습니다. 대신 AI Auditor가 사전 정의한 문서 결함을 발견하고, 수정된 문서에 대한 재검사 결과를 제공하는지 실제 프로그램으로 측정했습니다.

실험일: 2026-10-24. 앱 코드: `03a4be2d81b1e75045b88f00db2beb180b2eb758`. 기존 앱 코드는 수정하지 않았습니다. 사용자 PC의 실제 시연 문서와 구분한 합성 산출물이며, 문서 작성자·정답표 작성자·결과 대조자가 분리된 외부 검증은 아닙니다.

## 실행 전 확정한 조건

- 입력: DOCX 요구사항정의서 1개(요구사항 정의 6개), XLSX 추적표 1개(6개 행).
- 규칙: REQ-001 ID 누락·중복 / REQ-006 완전성 / REQ-018 양방향 추적성.
- 사전 주입 결함: ID 공란 1개, 서로 다른 정의의 ID 중복 1개, 구현대상·조건·범위·출력 미정 1개, 통합테스트 연결 공란 1개.
- 각 단계 1회. 결과를 보고 입력·파라미터를 바꾸거나 좋은 결과만 선택하지 않았습니다.
- 순서: 정답표·입력·프로토콜 저장 → 수정 전 검사 → 네 결함을 고친 입력의 검사 → 실제 지적과 정답표 대조.
- 실제 LlamaCppAIProvider와 LocalAIIssueAssessor를 사용했습니다. 가짜 응답·stub·자동 통과 판정을 쓰지 않았습니다.
- Linux 클라우드 CPU, Qwen3-4B Q4_K_M, llama.cpp b11312. seed 42, temperature 0.7, top-p 0.8, top-k 20, min-p 0, max_tokens 512. 원자료에 환경과 모델 SHA-256을 기록했습니다.

## 정답표 대조

| 정답 ID | 표적 결함 | 실제 결과 |
|---|---|---|
| G1 / REQ-001 | 비밀번호 변경의 ID 공란 | 검출 · 지적 1 |
| G2 / REQ-001 | 이메일 변경·회원 탈퇴의 REQ-104 중복 | 검출 · 지적 2 |
| G3 / REQ-006 | 주문 내역 조회의 구현대상·조건·범위·출력 미정 | **미탐** |
| G4 / REQ-018 | 회원 조회의 통합테스트 연결 공란 | 검출 · 지적 3 |

- 표적 결함 검출률 = 3 / 4 × 100 = **75%**. 미탐 = 1개.
- 수정 전 실제 지적 3개 모두 사전 결함과 대응했습니다. 관찰한 추가 지적(오탐)은 0개입니다.
- 정답표에 따라 네 결함을 모두 수정한 후 실제 지적은 **3건 → 0건**이었습니다.
- 수정은 검증 스크립트가 했습니다. 앱이 문서를 자동으로 고쳤거나 미탐 문제를 자동 해결했다는 뜻이 아닙니다.

새 서버 프로세스 준비 약 6.08초 후, 앱의 문서 파싱·실제 Local AI 검사·위험평가·감리판정·3형식 내보내기를 포함한 실행 구간은 수정 전 128.51초 / 수정 후 25.20초였습니다. 사람의 입력·검토 시간은 포함하지 않았습니다. 지적 수와 AI 호출 수가 달라 시간 차이를 속도향상률로 사용하지 않습니다.

## 해석의 한계

작은 단일 합성 사례이며 실제 현업의 전체 탐지율·오탐률이나 제품의 평균 정확도로 일반화하지 않습니다. 수정 후 0건은 이 입력에서 지적이 없었다는 관찰값이며 모든 결함이 없다는 보장이 아닙니다. REQ-006 미탐은 공개하며 제출 준비를 위해 검사 코드를 바꾸지 않았습니다.

수동 대비 시간절감률·인건비 절감액은 미측정입니다. Local AI 경로에 외부 AI API 호출이 없다는 점은 구성상의 사실이며 PC·전력비까지 0원이라는 비용효과는 아닙니다. 사용자 PC 시연의 434.06초·후보 7건은 별도 사례여서 이 실험과 섞어 비교하지 않습니다.
