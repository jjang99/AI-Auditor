# AI Auditor 구현 56개 Rule 공식근거 역검증

기준일: 2026-10-13

## 1. 목적

현재 실제 실행 중인 56개 Rule(MVP20 + P1 13 + P2 23)이, 2026-09-23부터 AI Auditor 전체의 감리 관련 Rule·판정·검사기준 검토 기본원칙으로 확정한 공식근거 우선순위와 얼마나 정합하는지 역검증한다.

이 문서는 기존 구현을 자동으로 폐기하거나 재코딩하기 위한 문서가 아니다.
먼저 **선정근거와 구현결과를 분리하여 검증 공백을 확인**하고, 해커톤 발표자료에서 과장 없이 설명할 수 있는 범위를 확정하기 위한 문서다.

중요:
- 2026-09-23의 공식근거 우선순위는 P3/P4 전용으로 처음 만든 기준이 아니다.
- 당시 `DECISIONS.md`에는 `AI Auditor의 감리 관련 Rule·판정·검사기준을 검토할 때` 사용하는 기본원칙으로 기록돼 있었다.
- 이후 최신 문서 정리 과정에서 이 원칙이 P3/P4 후속계획 아래에만 남아 오해 소지가 생겼다.
- 2026-10-13 역검증은 이 전역 원칙을 현재 구현 56개에도 다시 적용하여 확인하는 작업이다.

---

## 2. 공식근거 우선순위

1순위: **현행 정보시스템 감리기준**
2순위: **NIA 정보시스템 감리 수행 가이드**
3순위: **NIA 지능정보기술 감리 실무 가이드 및 분야별 감리 가이드**
4순위: **실제 감리에서 사용하는 지적사항·개선권고 등의 판정/조치 체계**
보조: **NIST / OWASP / CVSS 등 국제·기술 기준**

적용원칙:
- 국내 공식 감리기준/가이드를 국제기준보다 우선한다.
- 국제기준은 국내 감리 Rule의 단독 근거가 아니라 보조근거로 사용한다.
- 실제 감리결과서의 사례빈도만으로 공식근거 유무를 판단하지 않는다.
- 반대로 공식기준에 넓은 원칙이 있다고 해서 AI Auditor의 세부 Rule이 곧바로 직접근거를 가진다고 과장하지 않는다.

## 4. 역검증 판정기준

- **A — 국내 공식근거 직접/명확**
  - 정보시스템 감리기준 또는 NIA 감리 수행체계와 Rule 목적이 직접적으로 연결됨
  - 실제 감리사례가 함께 있으면 더욱 강한 근거

- **B — 국내 공식근거 간접/세부화**
  - 공식기준의 상위 점검목적에는 부합하지만 AI Auditor Rule이 더 세부적으로 구체화한 항목
  - NIA 분야별 가이드나 실제 감리사례로 보강 가능

- **C — 국내 직접근거 제한 / 국제·기술 보조근거 강함**
  - 주로 LLM/RAG/생성형 AI 특화 위험
  - NIST/OWASP 등에는 명확한 근거가 있으나 국내 감리기준에서 동일 수준으로 직접 규정된 것은 확인되지 않음
  - 발표 시 `국내 공식 감리기준 Rule`로 과장하지 않고 `AI 특화 보조 점검`으로 설명

- **M — 제품 종합/메타 Rule**
  - 독립적인 공식 감리 체크항목이라기보다 이미 발견된 하위 Issue를 종합·요약하는 제품 기능
  - 근거는 하위 Rule의 공식근거를 상속하며, 독립적인 규범근거가 있다고 표현하지 않음

- **X — 근거 재검토 필요**
  - 국내 공식근거, 사례근거, 국제 보조근거 모두 부족하여 현재 활성화의 타당성을 다시 검토해야 하는 항목

## 5. 1차 역검증 결과 요약

총 56개:
- **A 28개** — 국내 공식근거 직접/명확
- **B 19개** — 국내 공식근거 간접/세부화
- **C 6개** — 국내 직접근거 제한, NIST/OWASP 등 기술근거 중심
- **M 3개** — 종합/메타 Rule
- **X 0개** — 현재 단계에서 즉시 근거부족으로 비활성화해야 한다고 판정한 항목 없음

영역 관점:
- **비AI 45개 = A 28 + B 14 + M 3**
  - 국내 정보시스템 감리기준·NIA 수행체계·실제 감리사례와 전반적으로 정합
  - 다만 일부 세부 Rule은 공식기준의 넓은 점검목적을 자동화 가능한 단위로 세분화한 형태이므로 `공식기준에 동일 문구가 있다`고 표현하면 안 됨

- **AI 특화 11개 = B 5 + C 6**
  - 데이터 품질·평가·운영 모니터링·자원관리 등은 국내 지능정보/운영 가이드와 연결 가능
  - Prompt Injection, RAG 검색근거, Human-in-the-loop 등 최신 생성형 AI 특화항목은 NIST/OWASP 보조근거 비중이 큼
  - 따라서 해커톤 발표에서는 `국내 감리기준 + 국제 AI 위험기준을 보조로 결합`했다고 구분해 설명하는 것이 정확함

핵심 결론:
> 현재 56개가 공식근거와 무관하게 임의 구현된 것으로 보이지는 않는다. 특히 비AI 45개는 국내 감리체계와 높은 정합성이 확인된다. 다만 P1/P2 선정 당시 56개 각각에 대해 1→2→3→4순위 근거를 표로 남기지 않은 **문서화·검증 절차의 공백**이 실제로 있었고, AI 특화 일부 Rule은 국내 공식근거보다 국제 기술근거의 비중이 높다.

## 7. 현재 판단 — 구현을 당장 되돌려야 하는가?

현재 1차 역검증만으로는 **56개 중 즉시 삭제·비활성화해야 한다고 판정한 Rule은 없다(X=0).**

그러나 다음은 반드시 구분한다.

1. **A/B Rule**
   - 국내 공식 감리체계와 직접 또는 상위목적 수준에서 정합
   - 발표자료에서는 `공식 감리기준과 NIA 가이드를 기반으로 자동화 가능한 세부 점검항목으로 구조화`했다고 설명 가능

2. **C Rule**
   - 국내 공식 감리기준에서 동일한 LLM/RAG 특화 항목을 직접 확인했다고 말하면 안 됨
   - `NIST/OWASP 등 국제 기술기준을 보조로 반영한 AI 특화 점검`이라고 명확히 구분

3. **M Rule**
   - 독립 공식 Rule이 아니라 다른 검사의 실제 발견결과를 종합하는 제품 기능으로 설명

## 8. 이번 사태에서 확인된 절차상 문제

확인된 문제:
- 공식근거 우선순위는 2026-09-23부터 전역 원칙으로 존재했다.
- 그러나 2026-10-08~10 P1/P2 우선순위 선정·구현 문서에는 `AUDIT_EVIDENCE_MAPPING.md`의 실제 감리사례 근거등급이 전면에 기록됐고, 56개 각각의 1→2→3→4순위 공식근거 대조표를 먼저 남기지 않았다.
- 따라서 **결과 Rule의 상당수는 공식체계와 정합하지만, 선정절차를 증명하는 문서가 부족한 상태**가 되었다.

재발방지:
- 앞으로 Rule 신규선정 또는 우선순위 변경 전 반드시 `공식근거 매핑표`를 먼저 작성한다.
- `실제 감리사례 빈도`와 `공식 규범근거`를 서로 다른 열로 관리한다.
- 최신 Canonical 문서가 과거 상세 결정을 압축했더라도, 중요한 기준의 최초 확정시점이 문제되면 Git history와 이전 대화를 다시 확인한다.
- 발표자료에 넣을 근거도 `설계 의도`가 아니라 실제 저장된 문서/공식자료/코드로 확인한다.
