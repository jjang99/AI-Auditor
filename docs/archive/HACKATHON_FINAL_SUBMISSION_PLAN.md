# AI Auditor 해커톤 최종 제출 계획

## 1. 목적

현재 구현·검증 완료된 AI Auditor를 기준으로 해커톤 최종 제출물을 구성한다.

이번 제출 준비 기간에는 **P3/P4 49개 공식기준 재매핑과 추가 구현을 잠시 보류**한다.
P1/P2까지의 실제 실행 Registry 56개는 Freeze 상태를 유지하며, 새 결함이 확인되지 않는 한 재구현·재설계하지 않는다.

기준선:
- Full Catalog 105개
- 실제 실행 Registry 56개 = MVP20 + P1 13 + P2 23
- Rule 14 / AI 11 / Hybrid 31
- Parser 9종
- 감리자료 114개 실무 매핑
- MVP20 실증검증 및 우선 보완 5개
- 구현 56개 공식근거 2차 역검증 완료: A 28 / B 23 / C 2 / M 3 / X 0
- 전체 회귀검증 사용자 PC 실패 0건 확인
- Portable ZIP(EXE) 최종 검증 완료
- MSI 실제 설치 및 Local AI 검증 완료

## 2. 발표자료와 시연영상의 역할 분리

### 발표 PPT

발표자료는 **AI Auditor를 처음 보는 비IT 심사위원**을 기준으로 작성한다.

핵심 원칙:
- 개발 내부 용어를 나열하지 않는다.
- 필요한 영어용어는 `한글 설명 → 영어명` 순서로 함께 제시한다.
- 숫자(114/105/56/9)를 반복하기보다 **왜 그런 숫자가 생겼고 어떤 과정을 거쳤는지**를 설명한다.
- 공식근거 우선순위를 먼저 설명한다: `현행 정보시스템 감리기준 → NIA 감리 수행 가이드 → NIA 지능정보기술/분야별 가이드 → 실제 감리 판정·조치체계 → NIST/OWASP/CVSS 보조`.
- `MVP / P1 / P2`는 내부 단계명으로만 보조 표기하고, 본문에서는 `핵심 흐름 20개 → 실무근거 강한 13개 → 다음 우선순위 23개`로 설명한다.
- Rule / AI / Hybrid는 각각 `정형 규칙 검사 / AI 의미판단 / 혼합 검사`로 먼저 설명한다.
- 예시는 단어 수준이 아니라 `어떤 문서의 어떤 내용 → 무엇과 비교 → 어떤 결과를 제시`하는지까지 구체적으로 보여준다.
- 실제 구현 근거와 문서에서 확인되지 않는 내용은 임의로 만들어 설명하지 않는다.
- `105개 모두가 공식 감리기준 항목` 또는 `56개 모두가 고시 문구에 그대로 존재`하는 것처럼 표현하지 않는다.

발표 흐름 V9:
1. 작품명 / 한 줄 가치제안
2. 왜 필요한가 — 하나의 기능이 계약/RFP·요구사항·설계·시험·변경/FP에 걸쳐 관리되는 실제 업무상황
3. 검사기준의 공식근거 우선순위 — 국내 공식기준 우선, 실제 감리사례와 국제 기술기준의 역할 구분
4. 5개 검사영역과 Full Catalog 105 — 24+28+18+12+23의 의미와 영역별 실제 예
5. 105개 실무검증 — 감리자료 114개 / 요약→상세본문→전문별첨 3단계 교차검증 / 근거등급
6. 현재 실제 실행 56개 — 핵심 20 → 실무근거 강한 13 → 다음 우선순위 23, Registry의 의미
7. 검사기준을 실제 판단절차로 만드는 방법 — REQ-009 / CHG-010 교차문서 예시
8. 정형 규칙 검사(Rule) / AI 의미판단(AI) / 혼합 검사(Hybrid) 차이와 적용기준
9. 9종 문서를 읽는 구조 — 형식별 Parser → 공통 문서블록 → 검사 Engine, 스캔 PDF OCR 제외 이유
10. 왜 Local AI인가 — Qwen3-4B의 실제 역할·적용조건·한계, Impact/Likelihood와 최종 Matrix 경계
11. 실제 검사 예시 — 산출물 / 요구사항 / 인터페이스 / 변경 / FP / AI·RAG
12. 56개 공식근거 2차 역검증 + 기능검증 — A28/B23/C2/M3/X0, 5개 실증보완, 사람이 최종 확인하는 구조

### 3분 시연 영상

시연은 **실제로 어떻게 사용하는가**만 보여준다.

핵심 흐름:
`문서 선택 → 검사기준 선택 → 검사 시작 → Issue 근거 확인 → 조치 / Re-Inspect → History / Export`

PPT에서 설명한 개발배경·선정방법·Rule 설계방법을 영상에서 반복하지 않는다.
영상은 실제 UI와 실제 검사결과 중심으로 구성한다.

## 4. 제출 시 핵심 메시지

**AI Auditor는 사람을 대신 감사하는 도구가 아니라, 프로젝트 문서를 먼저 읽고 공식 감리기준·NIA 가이드·실제 감리사례를 근거로 누락·불일치·변경 미반영·산정오류·AI 품질위험 후보를 찾아, 담당자가 확인해야 할 범위를 좁혀주는 폐쇄망 대응형 사전 품질점검 도구이다.**

강조 포인트:
- 공식근거 우선순위는 AI Auditor 전체 공통 원칙
- 5개 영역 / Full Catalog 105는 AI Auditor 프로젝트의 전체 검사체계
- 감리자료 114개를 3단계로 교차검증해 각 Rule의 실무근거를 매핑
- 현재 실제 실행 56개
- 56개 공식근거 2차 역검증: A 28 / B 23 / C 2 / M 3 / X 0
- 정형 Rule + Local AI 의미판단 + Hybrid 조합
- 9종 프로젝트 문서 지원
- Local AI는 Qwen3-4B + llama.cpp를 Windows CPU에서 실행
- AI가 최종 Severity를 임의 결정하지 않고 Impact/Likelihood를 정해진 Matrix에 적용
- 감리사례보다 탐지범위가 좁았던 5개 Rule을 실제로 보완
- Portable EXE와 MSI 실제 설치본까지 검증
