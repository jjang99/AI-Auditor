감리결과서 114개 분석 결과를 현재 해커톤 MVP 실행 Rule 20개 및 실제 구현 코드와 대조하여,

## 2. 1차 실증판정과 보완 결과

1차 실증검증에서는 아래 5개 Rule이 실제 감리사례보다 현재 탐지범위가 좁아 `보완필요`로 판정되었다.

- `AUD-001` 필수 산출물 누락 점검
- `REQ-002` 요구사항 내용 중복 점검
- `REQ-003` 요구사항 모호성 점검
- `REQ-009` 요구사항 설계 반영 정합성 점검
- `FP-009` FP 산정값 재계산 검증

2026-10-09에 위 5개를 실제 감리사례 기반으로 최소 보완하고 전용 회귀테스트 및 전체 `python -m pytest -q`를 사용자 PC에서 재수행하였다.

**결과: 우선 보완 5개 모두 구현 및 회귀검증 완료, 전체 pytest 실패 0건 확인.**

이는 MVP 20개 전체가 모든 종류의 실무사례를 완벽하게 포괄한다는 뜻은 아니다.
아래에 남겨둔 `부분적합` 및 `실무사례 제한` 항목은 향후 정밀 확장대상으로 유지한다.

# 4. 우선 보완 5개 상세

## AUD-001 — 필수 산출물 누락 점검

실제 감리 방식에 맞춰 다음 기준을 적용한다.

`산출물목록 → 테일러링 결과 확인 → 현재 제출대상 산출물 확정 → 실제 업로드 파일과 비교`

현재 구현:
- 산출물목록을 1순위 기준으로 사용
- 테일러링에서 `미적용/제외` 항목은 누락대상에서 제외
- `시기미도래/해당없음` 항목은 현재 누락으로 판정하지 않음
- 산출물목록이 없고 테일러링만 있는 경우 명시적 적용항목만 보수적으로 사용
- 기준자료가 없으면 임의 표준 산출물목록을 만들어내지 않음
- UI Freeze 변경 없이 업로드 문서 자체에서 기준을 추출

관련 구현:
- `rules/core/deliverable_baseline.py`
- `rules/core/document_engine.py`

## REQ-002 — 요구사항 내용 중복 점검

기존 문제:
- 거의 동일한 문자열만 AI 비교대상으로 전달되어 의미중복 탐지범위가 지나치게 좁았음.

보완:
- 요구사항 ID를 제외한 의미/명칭 후보를 비교하고, 표현이 달라도 동일 기능·의미일 가능성이 있는 후보를 AI 판단단계로 전달
- 무관한 요구사항은 후보쌍에서 제외하도록 회귀테스트 추가

관련 구현:
- `rules/core/ai_engine.py`
- `tests/test_audit_case_regressions.py`

## REQ-003 — 요구사항 모호성 점검

기존 문제:
- `적절히`, `필요시` 등 일부 표현 중심이라 실제 감리의 정량기준 미정 사례를 놓칠 수 있었음.

보완:
- 응답시간·처리량·횟수·기간 등 정량목표가 필요한데 값이 없는 후보 탐지
- `협의 후 확정` 등 미확정 조건 탐지
- 명시적인 숫자/단위가 존재하는 정상 요구사항은 오탐하지 않도록 회귀테스트 추가

관련 구현:
- `rules/core/hybrid_engine.py`
- `tests/test_audit_case_regressions.py`

## REQ-009 — 요구사항 설계 반영 정합성 점검

기존 문제:
- 문서 한 개씩 검사하여 요구사항정의서와 화면/프로그램/데이터/인터페이스 설계서를 서로 직접 비교하지 못했음.

보완:
- 요구사항정의/기술/추적 문서에서 요구사항 ID와 내용을 추출
- 화면/인터페이스/테이블/데이터/프로그램/아키텍처/유스케이스/클래스 등 설계 산출물에서 관련근거 탐색
- 요구사항 ID 직접연결을 최우선으로 사용
- ID가 없으면 충분한 핵심어가 겹치는 경우만 보수적으로 후보화
- 연결근거가 전혀 없다는 이유만으로 즉시 `미반영`을 단정하지 않음
- 저사양 Local AI 처리를 위해 근거를 제한된 배치로 구성

관련 구현:
- `rules/core/requirement_design_alignment.py`
- `app/services/inspection_service.py`
- `tests/test_audit_case_regressions.py`

## FP-009 — FP 산정값 재계산 검증

기존 문제:
- `15 + 25 + 10 = 55`와 같은 단일 문자열 산식만 검증 가능했음.

보완:
- 기존 단일 산식 검사는 유지
- XLS/XLSX Parser의 행 구조를 이용한 구조형 FP 계산 추가
- 기능유형 `ILF/EIF/EI/EO/EQ` 인식
- 명시적 복잡도가 있으면 표준 가중치로 재계산
- 복잡도가 없고 `RET/FTR + DET`가 모두 있으면 표준 복잡도 행렬로 복잡도를 계산한 뒤 재산정
- 기능개수 열이 있으면 `기능개수 × 가중치`로 계산
- 계산 근거가 부족한 행은 추정하지 않음

관련 구현:
- `rules/core/fp_calculator.py`
- `rules/core/document_engine.py`
- `tests/test_fp009_audit_regressions.py`
